# Push

Phones not running Aspen are woken through their app's push relay or a UnifiedPush distributor, as `spec/push.md` describes; the relay, which alone holds a published app's Apple and Google credentials, is its own repository (`aspen-push-relay`). Every push is Web Push: a pointer (`app::push::Pointer`: `message`, `read`, or `deleted`, naming a channel and a message, and a `badge` count) encrypted to the phone (RFC 8291, `app::push::webpush`, checked against RFC 8291's own example) and signed with the deployment's push key (RFC 8292), a P-256 key in `push_key` made by the first server to start, like the federation key, and advertised as `push.applicationServerKey` in `GET /auth/methods`. `POST /users/@me/push-subscriptions` registers the calling sign-in's phone (`push_subscription`, one per refresh token, which cascades, so signing out stops it); pushes go to HTTPS endpoints at public addresses only, through the same client as calls to other deployments, and a subscription whose endpoint answers `403`, `404`, or `410`, or made for a key since replaced, is dropped. What wakes whom is decided by one task per API server (`app::push::spawn_dispatcher`) reading the event stream through the durable JetStream consumer `aspen_push` they share, so each event is handled once, each DM copy deduplicated in Valkey: a new message wakes the other people of its DM, or those it tags (by name, a role, or everyone) who may view its channel, never its author, anyone who blocked them here, anyone who muted the channel (a thread counting as its parent), or anyone active on Aspen at that moment; each is sent `message` with `Urgency: high`, up to `FAN_OUT` people at once, their phones read in one query. Whom a message woke is remembered in Valkey for a week, so reading that channel elsewhere sends `read` and deleting the message `deleted`, both `Urgency: low`, which relays whose iOS app cannot hide a notification leave undelivered. Events are published before their transaction commits, so the dispatcher waits for the message, or the read position, to be there before it reads anything else. `scripts/dev_push.py` checks all of it against the development deployments, standing in for relay and phone.
