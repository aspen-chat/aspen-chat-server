# Message links

A message whose text links to messages of this deployment shows each beneath it, as a link preview shows a page (`app::message_link`). A link is any URL under `/communities/` or `/dms/` ending in `messages/{id}`, the routes the clients give messages (`https://{deployment}/communities/{c}/channels/{ch}/messages/{m}`, `/dms/{ch}/messages/{m}`); its host is not checked, since a message id names one message anywhere, and a link under `/at/{domain}` is to another deployment's message by its own route and is left alone. The links are read with the same walk over the Markdown as link previews (`app::link_preview::extract_urls`, skipping code), and link previews leave message links out, so the server never fetches its own web client.

Posting or editing a message records the ids it links to, in order, each once, at most `MAX_LINKS` (5) and never itself, as `message.linked_messages` and the record's `linkedMessages`; an edit that changes the text announces the new set in its `update` event. A command links nowhere, and a warning shows what it is about through its own `warning` field (see Reports).

Who may see what is decided when the links are read, for each reader: message reads sideload `include=linked` as `included.linkedMessages`, one record per message linked with its `state` (`available`, `deleted`, or `unavailable`) and, for an available message in a community, the community its route names, and put the available messages themselves among `included.messages`, their authors and attachments coming with the read's own when those are asked for. A message the reader may not read is `unavailable`; a deleted one is `deleted` only where the reader may read its channel, so its having existed is no one else's to learn. Links are recorded, never followed: the messages a linked message links to are not read with it.
